# Project instructions

This is a standard Spring Boot backend with a `__WIZ_FRONTEND__` frontend.

- This project was generated by WIZ Spring `1.2.2`. Its baseline is Java release 25,
  Spring Boot `4.1.1`, Boot-managed Spring Framework `7.0.9`, springdoc `3.1.0`,
  Maven Wrapper `3.9.15`, and Node.js
  `^22.22.3 || ^24.15.0 || >=26.0.0`.
- Treat `pom.xml`, `package.json`, and the lockfile as the executable version sources.
  When upgrading them, update `README.md` and all affected `docs/ai` files together.
- Use `jakarta.*` for Jakarta EE Servlet, Persistence, and Validation APIs. Do not
  reintroduce their legacy `javax.*` packages.
- Backend code lives only under `src/main/java`; do not add Java handlers to frontend folders.
- Keep the application flow `Controller -> model.Struct -> model/<feature>/<Feature>Struct`.
- Put endpoint-only request records inside their Controller and safe response records inside the Feature Struct. Never expose JPA entities as JSON.
- Keep each business aggregate in one `model/<feature>` package with its Struct, Entity, Repository, and related types. Do not add a deeper `entity`, `repository`, or `dto` package.
- Do not create global `service`, `domain`, `repository`, `dto`, `dao`, `support`, `common`, `util`, `manager`, or `helper` packages. A Feature Struct owns use cases and transactions.
- Use `config`, `security`, `exception`, and `web` only for the responsibility named by the package. Do not merge them into a catch-all package.
- Business API controllers use `web.ApiController("/resource")`. Never repeat the configured `/api` prefix in a controller.
- `app.api.prefix` in `src/main/resources/application.yml` is the single API-prefix source of truth.
- Use `module/<feature>` only for a genuinely reusable backend boundary with a small public contract and independent tests. Never create a backend `portal` package or mix frontend files into a Java module.
- Keep `model.Struct` stateless: it only exposes typed feature accessors. Request/session state belongs in the request-scoped `security.SessionContext`.
- Generated frontend output belongs in `target/generated-resources/frontend`; do not edit it.
- `bundle/` and `target/` are generated outputs and must not be edited or committed.
- Project-local configuration and its safe defaults belong in the generated root `.env`.
  Edit that file directly and never introduce a copy or rename step. Generated npm
  scripts and a development service read `.env`; secrets must come from exported variables
  or an external service env file. An environment-only change requires a process/service
  restart; an ordinary source edit does not.
- Run `npm run frontend:build` for the frontend, `npm run backend:build` for Spring, `npm run build` for both, and `npm run bundle` for deployment output.
- Never finish a source-code task after editing files only. Run `./mvnw test` and
  `npm run backend:build` after backend changes, and run the frontend-specific test plus
  `npm run frontend:build` after frontend changes. Use `npm run build` when both sides or
  shared build scripts change.
- `npm run dev` owns the live-development lifecycle. It performs the initial builds,
  watches backend and frontend sources, recompiles Java, and lets Spring DevTools restart
  the application only after compilation succeeds; a failed compile leaves the last good
  application running. Do not stop and restart it for ordinary source edits: wait for the
  watcher build to succeed and, for backend edits, for the restarted application to report
  that it has started. Treat watcher errors as failed work and fix them before finishing.
- Dependency, `pom.xml`, `package.json`, or watcher/build-configuration changes are the
  exception: run the full relevant build and restart `npm run dev` so the process classpath
  and watcher configuration are recreated.
- Do not add a `.wiz` directory or a private WIZ build package. Build support is committed under `scripts/`.
- A deployment bundle has exactly four top-level entries: `application.jar` (or the JSP
  `application.war`), `public/`, `.env`, and `docker-compose.yaml`. It must run with JDK 25+
  directly or through the application-only Compose service. Never introduce a bundle or
  installed-service runtime dependency on the WIZ Spring CLI, Node.js, npm, or Maven.
- Keep Nginx and Apache HTTP Server out of the bundle and Compose. Host-managed examples
  belong in `deploy/nginx/default.conf.example` and `deploy/apache2/wiz.conf.example`.

Read `docs/ai/backend-spring.md`, `docs/ai/frontend.md`, and `docs/ai/deployment.md` before structural changes.
