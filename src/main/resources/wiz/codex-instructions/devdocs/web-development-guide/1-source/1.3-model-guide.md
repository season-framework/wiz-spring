# Model And Struct Guide

Model은 domain 로직과 persistence를 담당한다. App API는 model을 조립하고 response를 반환하는 얇은 계층으로 유지한다.

## 위치

```text
src/model/
  Struct.java
  AuthService.java
  SessionService.java
  db/UserEntity.java
  struct/UserStruct.java

src/portal/post/model/
  PostStruct.java
  db/PostEntity.java
  struct/PostService.java
```

## Root Struct


```java
import com.wiz.runtime.WizContext;

public final class Struct {
    private final UserStruct user;

    public Struct(WizContext wiz) {
        this.user = new UserStruct(wiz);
    }

    public static void warmup(WizContext wiz) {
        new Struct(wiz);
    }

    public UserStruct user() {
        return user;
    }
}
```

`Struct.warmup(WizContext)`은 서버 시작 시 현재 app에 대해 호출되는 선택 hook이다. DB connection pool, JPA metadata/schema, idempotent seed, SDK/cache preload처럼 첫 요청 전에 공통으로 필요한 비용 큰 초기화만 넣는다. 사용자/session 의존 작업, 긴 batch, 전체 데이터 scan, non-idempotent 외부 호출은 warmup에서 제외한다.

## API에서 사용

```java
Struct struct = wiz.models().get("struct", Struct.class);
return wiz.response().ok(struct.user().list("", ""));
```

## 의존성

- JPA, JDBC driver, SDK는 workspace `pom.xml`에 둔다.
- datasource와 외부 API 설정은 `config/application.yml` 또는 namespace yml에 둔다.
- 요청 단위 resource는 `wiz.onCleanup(...)`으로 닫고, runtime cache와 생명주기가 맞는 장기 resource는 `wiz.projectRuntime().onClose(...)`로 닫는다.
- project-local Spring/JPA context, connection pool, SDK client처럼 core Spring context 밖에 있는 resource는 `wiz.observability()`로 health, gauge, transaction/timer metric을 등록한다.
