# Socket Guide

기본 frontend `wiz.socket()`은 native WebSocket endpoint `wiz.socket.path/{appId}`를 사용한다. 기본값은 `/wiz/app/{appId}`다. Spring runtime은 Socket.IO v4 HTTP long-polling endpoint `/socket.io/`도 유지하지만 namespace는 native WebSocket과 같은 `wiz.socket.path/{appId}`를 사용한다.

Socket connect와 event dispatch는 app metadata의 `controller` 정책을 먼저 통과한다. `controller: "user"` 또는 `"admin"`인 app의 socket은 HTTP API/route와 같은 session/auth 경계를 따른다.

## 위치

```text
src/app/page.chat/
  app.json
  socket.java
```

## 구현


```java
import java.util.Map;

import com.wiz.socket.SocketController;
import com.wiz.socket.SocketEventHandler;
import com.wiz.socket.SocketEventResult;
import com.wiz.socket.SocketRoomRegistry;
import com.wiz.socket.SocketSession;

public final class PageChatSocketController implements SocketController {
    public String appId() {
        return "page.chat";
    }

    public Map<String, SocketEventHandler> handlers() {
        return Map.of("send", this::send);
    }

    private SocketEventResult send(SocketSession session, Map<String, Object> payload, SocketRoomRegistry rooms) {
        return new SocketEventResult(true, "chat.message", payload.getOrDefault("text", "").toString());
    }
}
```


## Frontend

```ts
const socket = this.wiz.socket();
socket.emit("send", { room: "lobby", text: "hello" });
socket.on("chat.message", (message) => console.log(message));
```

Socket handler는 build된 bundle의 class를 dispatch 시점에 읽는다. `socket.java`를 수정한 뒤 `wiz-spring build`가 끝나면 다음 연결 또는 메시지부터 반영된다.

## SSE와 프로젝트별 실시간 구현

Core는 모든 SSE, broker, multi-instance broadcast 조합을 공통 기능으로 제공하지 않는다. 서버에서 client로만 흘리는 진행률, 알림, 빌드 로그 같은 기능은 실제 프로젝트의 route/controller source에서 Spring MVC `SseEmitter` 또는 별도 WebFlux endpoint로 구현한다.

운영에서 여러 instance가 같은 room이나 stream을 공유해야 하면 workspace dependency와 source에서 Redis pub/sub, message broker, managed realtime service 중 하나를 선택한다. 이때 heartbeat, reconnect id, send timeout, max connection, overflow/drop policy, 인증된 사용자별 stream 권한을 앱 코드에 명시한다.
