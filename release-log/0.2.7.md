# WIZ Spring 0.2.7

상태: released (`0.2.7` 태그, 2026-07-23)

WIZ Spring `0.2.7`은 장기 실행 중 project runtime 교체 안정성, 실행 로그와 CLI 사전조건, 반복 가능한 Git 배포 및 내장 OpenAPI 문서를 보강하는 패치 릴리즈입니다.

## 주요 변경

- 요청이 사용 중인 project classloader와 resource는 마지막 lease가 끝난 뒤 닫고, 고정 parent classloader와 build별 snapshot으로 재빌드 경쟁을 차단합니다. retired loader를 붙잡던 Spring reflection/bean cache와 project JDBC driver도 정리하며, 한 JDBC cleanup callback이 실패해도 나머지 driver 정리는 계속합니다.
- build marker에 runtime 전용 digest를 기록합니다. 화면·정적 산출물만 바뀐 build는 실행 중인 JPA/classloader를 재생성하지 않고, Java API·dependency·config·runtime metadata가 바뀐 경우에만 새 runtime으로 교체합니다. marker가 게시 중 잠시 보이지 않으면 마지막 완료 runtime을 유지합니다.
- `run --log`가 stdout/stderr 전체를 계속 tee하면서 10 MiB 단위로 회전하고 현재 파일과 archive 14개만 유지합니다.
- runtime/handler 오류에 request ID가 포함된 원인 stack trace를 남기고 `service logs`로 journal과 application log 위치를 확인합니다.
- CLI가 Java WIZ marker/구조, 완료된 동일 버전 bundle, Maven Wrapper/PATH Maven, launcher JAR/Java를 실행 전에 검증합니다.
- Maven dependency와 bundle은 staging 성공 후 교체하며, 실패하면 clean/phase와 관계없이 직전 정상 bundle을 보존합니다. CycloneDX BOM도 bundle 안에서 marker와 함께 게시하고, Java source/dependency/frontend의 이전 산출물이 새 bundle에 섞이지 않도록 입력과 정리 범위를 강화했습니다.
- 반복 build는 안정적인 Maven 입력과 게시 JAR hash가 같으면 dependency 해석 process를 생략하고, Boot fat JAR의 javac classpath 추출물도 원본 digest별 외부 cache에서 무결성을 확인해 재사용합니다. workspace/local Maven model·사용자 settings·Maven option에서 확인한 SNAPSHOT·version range·LATEST/RELEASE, 실제 profile activation과 project systemPath, Maven `--clean`은 다시 해석하고, 손상된 cache는 해당 항목만 안전하게 재생성합니다.
- 기본 Angular lockfile과 `npm ci`로 서버별 dependency 차이를 줄이고, 일반 build는 `node_modules`와 Angular 증분 cache를 순회·삭제하지 않으며 package/lock/`.npmrc` fingerprint가 바뀔 때만 다시 설치합니다. lockfile이 없는 project는 registry 변화가 고정되지 않으므로 매 build에서 `npm install`을 다시 수행합니다. 재설치할 때는 Angular cache를 비우고 불완전한 CLI 입력은 npm 실행 전에 fallback 처리합니다.
- `/v3/api-docs`, `/v3/api-docs.yaml`, `/swagger-ui.html`을 내장하고 App API 및 WIZ Route metadata를 문서화합니다. Swagger UI 호출 기능은 기본 비활성화합니다.
- systemd script는 Java process를 `exec`하고 workspace 소유자 계정으로 실행합니다. 서비스별 log directory, 외부 runtime/cache/state 환경 고정, 재시작 간격, 종료 timeout, 정상 SIGTERM 상태와 제한된 umask도 설정합니다.
- workspace 정규 경로별 외부 filesystem build lock 안에 package 변경과 build를 함께 묶고, dependency backup 교체로 동시 build 및 교체 실패 시 source와 기존 dependency 손상 가능성을 줄입니다. 사용이 끝난 JVM 내부 lock entry도 제거합니다.
- 내부 source staging은 `build/target/work/source`를 사용하고 build lock은 외부 사용자 state, runtime snapshot은 외부 사용자 disk cache, npm cache는 기본 사용자 cache, MCP 상태는 외부 사용자 state 경로에 저장해 프로젝트 내부의 숨김 framework 디렉터리를 제거합니다. 외부 framework 디렉터리는 owner-only 권한을 적용하고, MCP state는 file lock/atomic replace를 사용하며, 강제 종료로 남은 snapshot은 host/process-start namespace 안에서 다음 기동 때 workspace 전체에서 정리합니다.

## 운영 적용 주의사항

`src/angular/package-lock.json`은 Git에 포함하고, `config/wiz.yml`에는 `workspace: java`를 유지한 뒤 `0.2.7` runtime으로 clean build합니다. 실제 config/data와 `build/`, `bundle/`은 Git으로 옮기지 말고 release checkout에 별도로 주입합니다. 생성된 systemd unit은 workspace 소유자를 기본 `User=`로 사용하므로 build CLI도 그 계정으로 실행하고, 위치를 바꿀 때는 같은 절대 `WIZ_SPRING_RUNTIME_DIR`을 사용합니다. 대용량 snapshot 위치는 `WIZ_SPRING_CACHE_DIR`로 별도 지정할 수 있으며 모든 override 경로는 workspace 밖이어야 합니다.

## 검증

- Maven 전체 테스트 `278`개 통과, `./mvnw -q -DskipTests package`와 `wiz-spring 0.2.7` 버전 출력을 확인했습니다.
- 실제 `create`로 project를 만들고 초기 clean build, 빈 port 실행, health/login/dashboard/members/portal API, OpenAPI JSON/YAML, Swagger UI를 확인했습니다.
- 화면 변경 build에서 `runtimeDigest`와 runtime load/retire 횟수가 유지됐고, Java API를 6회 교체한 뒤 Full GC 기준 `ProjectRuntimeClassLoader`, `DriverInfo`, `org.sqlite.JDBC`, SQLite native mapping이 각각 1개만 남았습니다. metaspace 사용량은 약 87.6 MiB였습니다.
- Maven dependency와 npm package를 실제 추가·사용·반복 build·제거해 cache hit와 stale artifact 제거를 확인했고, workspace 및 `build` 아래에 `.wiz` directory가 생성되지 않음을 확인했습니다.
- 같은 host 교차 benchmark에서 Maven dependency 단계 중앙값은 94.0%, Angular reconstruct 중앙값은 59.0% 줄었습니다. Boot `java-compile`과 Angular frontend 자체는 유의한 시간 개선으로 분류하지 않았습니다.
