# WIZ Spring 0.2.7

상태: working (미태그)

WIZ Spring `0.2.7`은 장기 실행 중 project runtime 교체 안정성, 실행 로그와 CLI 사전조건, 반복 가능한 Git 배포 및 내장 OpenAPI 문서를 보강하는 패치 릴리즈 후보입니다.

## 주요 변경

- 요청이 사용 중인 project classloader와 resource는 마지막 lease가 끝난 뒤 닫고, 고정 parent classloader와 build별 snapshot으로 재빌드 경쟁을 차단합니다.
- `run --log`가 stdout/stderr 전체를 계속 tee하면서 10 MiB 단위로 회전하고 현재 파일과 archive 14개만 유지합니다.
- runtime/handler 오류에 request ID가 포함된 원인 stack trace를 남기고 `service logs`로 journal과 application log 위치를 확인합니다.
- CLI가 Java WIZ marker/구조, 완료된 동일 버전 bundle, Maven Wrapper/PATH Maven, launcher JAR/Java를 실행 전에 검증합니다.
- Maven dependency는 staging 성공 후 교체하며, 기본 Angular lockfile과 `npm ci`로 서버별 dependency 차이를 줄입니다.
- `/v3/api-docs`, `/v3/api-docs.yaml`, `/swagger-ui.html`을 내장하고 App API 및 WIZ Route metadata를 문서화합니다. Swagger UI 호출 기능은 기본 비활성화합니다.
- systemd script는 Java process를 `exec`하고 재시작 간격, 종료 timeout, 정상 SIGTERM 상태와 제한된 umask를 설정합니다.
- workspace filesystem build lock과 dependency backup 교체로 동시 build 및 교체 실패 시 기존 dependency 손상 가능성을 줄입니다.

## 마이그레이션 주의사항

기존 workspace는 `src/angular/package-lock.json`을 생성해 Git에 포함하고, `config/wiz.yml`에 `workspace: java`가 있는지 확인한 뒤 `0.2.7` runtime으로 clean build해야 합니다. `run`은 이전 runtime version의 bundle을 거부합니다. 실제 config/data와 `build/`, `bundle/`, `.wiz/`는 Git으로 옮기지 말고 release checkout에 별도로 주입합니다.

세부 운영 점검과 release-directory 배포 절차는 [`docs/reviews/eegvhudvcsffxtopyqfcsfdwvzddwcyz.md`](../docs/reviews/eegvhudvcsffxtopyqfcsfdwvzddwcyz.md)에 기록했습니다.
