# WIZ Spring 0.2.0

릴리즈 날짜: 2026-07-08

WIZ Spring `0.2.0`은 build 이후 산출물 구조를 외부에서 읽기 쉬운 Spring Boot/Maven project 형태로 정리한 릴리즈입니다. 원본 WIZ `src/**` 개발 방식과 `bundle/**` runtime 계약은 유지하되, 공개 build surface와 내부 staging 경계를 분리했습니다.

## 주요 변경

- `ProjectBuildLayout`을 추가해 build staging, generated Java source, target artifact 경로를 한 곳에서 관리합니다.
- WIZ source staging을 `build/src/**`에서 `build/.wiz/source/**`로 옮겨 내부 staging과 공개 build 산출물을 분리했습니다.
- Generated Java source를 `build/src/main/java`, runtime config resource를 `build/src/main/resources`에 생성합니다.
- Java compile output, dependency jar, app API jar, frontend output, CycloneDX BOM을 `build/target/classes`, `build/target/dependency`, `build/target/app-api.jar`, `build/target/frontend`, `build/target/bom.json`으로 정리했습니다.
- Legacy build 산출물(`build/classes`, `build/app-api.jar`, `build/main`, `build/src/app` 등)을 rebuild 전에 제거하도록 정리했습니다.
- Bundle runtime 계약은 기존처럼 `bundle/classes`, `bundle/app-api.jar`, `bundle/src/**`, `bundle/www`를 유지합니다.
- Generated package를 Spring 계층형 명칭으로 정리했습니다. API는 `web.api`, route는 `web.route`, socket은 `realtime.socket`, controller guard는 `security.guard`, model은 `application`/`domain`/`infrastructure`, portal model은 `module.{package}` 아래로 생성합니다.
- 기존 `api`, `socket`, `route`, `controller`, `model`, `portal.*.model` FQCN은 metadata normalization, runtime lookup, source rewrite 단계에서 새 package로 정규화합니다.
- `ModelRegistry`, `ProjectExtensionLoader`, `ProjectWarmupService`가 새 package 후보와 legacy package 후보를 함께 탐색하도록 보강했습니다.
- `AngularBuildService`와 `AngularSourceStagingService`가 내부 staging 경로와 `build/target/frontend` output을 사용하도록 갱신했습니다.
- MCP dependency 정보와 supply-chain manifest가 새 `build/target/dependency`, `build/target/bom.json` 위치를 가리키도록 갱신했습니다.
- README에 build 공개 구조, 내부 staging 경계, generated package mapping을 문서화했습니다.
- 기본 sample source import를 새 generated package 구조에 맞게 갱신했습니다.
- `docs/reviews/lzouwnemdykmrtduswstoziwcxqkvaxy.md`에 build 산출물 구조 전환 결정과 남은 리스크를 기록했습니다.

## 업그레이드 안내

- Runtime artifact는 `target/wiz-spring-0.2.0.jar`입니다.
- 외부 도구가 기존 `build/main`, `build/classes`, `build/app-api.jar`, `build/dist/build`, `build/src/app` 등을 직접 읽고 있었다면 새 `build/src/main/java`, `build/src/main/resources`, `build/target/**`, `build/.wiz/source/**` 경로로 갱신하세요.
- Runtime bundle을 소비하는 배포 흐름은 기존 `bundle/**` 계약을 유지하므로 별도 변경이 필요하지 않습니다.
- 기존 project source의 legacy FQCN은 build/runtime에서 새 package로 정규화되지만, 새 source를 작성할 때는 README의 generated package mapping을 기준으로 맞추는 것을 권장합니다.
