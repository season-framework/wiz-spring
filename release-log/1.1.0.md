# WIZ Spring 1.1.0

상태: released (`1.1.0` 태그, 2026-08-30)

WIZ Spring `1.1.0`은 표준 Spring Boot/Maven 실행 모델과 1.0의 HTTP 계약을 유지하면서,
새로 생성되는 backend를 얕은 업무 단위 구조로 재구성한 릴리스입니다.

## Backend 구조

- 기본 흐름을 `Controller -> model.Struct -> model/<feature>/<Feature>Struct -> Repository`로 고정했습니다.
- `AuthController`, `MemberController`, `ProfileController`를 `UserController`로 묶고 Controller는 Root `Struct` 하나를 통해 업무 기능에 진입합니다.
- `service`, 전역 `domain`/`repository`, `api/model`을 제거하고 각 Struct·Entity·Repository를 `model/user`, `model/post`, `model/chat`, `model/dashboard`에 함께 배치했습니다.
- endpoint 전용 request record는 Controller, 안전한 response record는 Struct에 중첩했습니다. Entity JSON 노출은 계속 금지합니다.
- session 상태는 scoped proxy를 사용하는 request-scoped `security/SessionContext`로 분리했습니다.
- API 설정·예외·HTTP 기반 기능을 각각 `config`, `exception`, `web`으로 분리하고 포괄적인 `support` package는 만들지 않습니다.
- sample production Java 파일은 31개에서 23개, 공통 파일을 포함한 전체는 36개에서 28개로 줄었습니다.

## Module과 인스트럭션

- 모호한 backend `portal` 대신, 실제 재사용 계약과 독립 테스트가 있는 경우에만 `module/<feature>`를 사용하도록 기준을 정했습니다.
- `AGENTS.md`와 backend AI 지침에 model 최대 깊이, 금지 package, nested record, transaction, request scope, module 승격·auto-configuration 기준과 1.0 선택적 이동 순서를 명시했습니다.
- 생성 manifest와 generator test가 공통 5개·sample 23개, `model/<feature>` 최대 깊이, 금지 package를 검증합니다.
- Angular WIZ의 `src/portal`은 frontend 전용 legacy source namespace이며 Java backend module과 무관하다는 경계를 명시했습니다.

## 호환성과 버전

- 기존 API path, status, JSON field, session 권한, JPA schema/query, SSE cursor/commit 이후 publish 계약을 유지했습니다.
- 기존 1.0 생성 프로젝트는 generator runtime에 의존하지 않으므로 자동 이동하지 않습니다. 새 구조는 fresh create에 적용하고, import에는 기존과 같이 sample backend를 주입하지 않습니다.
- generator, 다섯 template의 Maven/npm version, Docker helper와 문서를 `1.1.0`으로 동기화했습니다.
