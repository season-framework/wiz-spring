# WIZ Spring 1.0.0

상태: released (`1.0.0` 태그, 2026-08-27)

WIZ Spring `1.0.0`은 `0.2.8`을 포함한 `0.2.x`의 WIZ runtime과 변환 build를
이어가는 호환 릴리스가 아니라, 프로젝트 생성기 중심의 새 기준선입니다. 생성된
backend는 표준 Spring Boot/Maven 프로젝트이며 frontend build와 배포 bundle도
프로젝트에 포함된 script만으로 수행합니다.

## 호환성 주의

- `1.0.0`은 `0.2.8` 프로젝트의 인플레이스 업그레이드가 아닙니다.
- 기존 workspace의 WIZ backend 변환 구조, runtime 설정, build/bundle 산출물,
  systemd unit을 자동 탐지·변환·마이그레이션하지 않습니다.
- 기존 `0.2.8` 프로젝트는 해당 버전의 runtime/tooling으로 유지하거나, 새 `1.0`
  프로젝트를 생성한 뒤 표준 Spring 및 선택한 frontend layout으로 수동 이전해야
  합니다.
- `create --path`, `create --uri`, `service`는 `0.2.8` workspace나 bundle을 직접
  업그레이드하는 명령이 아닙니다.

## 주요 변경

- `create --template`에 `angular-wiz`, `angular`, `react`, `html`, `jsp`를 제공하고
  `angular-wiz`를 기본값으로 사용합니다.
- `create`가 파일을 생성하기 전에 JDK 21+, 지원되는 Node.js LTS 범위, npm 10+를
  검사하고 부족하거나 지원되지 않는 도구를 한 번에 안내합니다.
- frontend 종류는 root `package.json`의 `wiz.frontend`와 표준 프로젝트 파일로
  식별하며 `.wiz` 디렉터리를 만들지 않습니다.
- Angular WIZ compiler와 watcher를 `scripts/wizbuild.mjs`, `scripts/wizwatch.mjs`,
  `scripts/wiz/*.mjs`로 프로젝트에 포함합니다. 외부
  `@season-framework/wiz-frontend` package를 설치하지 않습니다.
- 생성된 backend는 `src/main/java`의 일반 Spring source를 Maven Wrapper로 직접
  build합니다. WIZ Java source 변환이나 runtime dispatcher는 사용하지 않습니다.
- 새 프로젝트에는 세션 인증, H2/JPA, members/posts/profile CRUD, dashboard, SSE chat과
  이를 사용하는 다섯 종류의 반응형 frontend sample을 제공합니다. import에는 sample을
  주입하지 않습니다.
- `@ApiController`에만 중앙 API prefix를 적용합니다. 기본값은 `/api`이며
  `/api/v2` 같은 고정 prefix와 Spring MVC path versioning을 지원합니다.
- `npm run dev`가 Spring, backend compile watcher, frontend watcher를 함께 실행하고
  `npm run build`와 `npm run bundle`이 통합 build와 배포 bundle 생성을 담당합니다.
- bundle에 backend JAR 또는 WAR, frontend 정적 파일, configuration, Nginx/Apache2
  설정, Docker Compose, manifest, SHA-256 checksum을 함께 게시합니다.
- `wiz-spring service install`은 bundle artifact를 직접 실행하는 systemd unit을
  생성하고 재부팅 후 자동 기동하도록 enable합니다. 실행 로그는 journald에 남기며
  checksum과 service user 접근 권한을 설치 전에 검증합니다.
- 생성 프로젝트에 공통 Spring/deployment 지침과 template별 frontend AI 지침을
  주입합니다.

## 1.0 경계

- `wiz-spring` JAR는 새 프로젝트 생성과 선택적인 systemd service 관리에만
  사용합니다. 생성된 프로젝트의 build, watch, 실행, bundle에는 필요하지 않습니다.
- 이전 WIZ backend 변환 구조, runtime bridge, MCP mutation workflow를 위한 호환·탐지·
  migration 분기는 포함하지 않습니다.
- 기존 프로젝트를 가져오려면 backend가 이미 `src/main/java`의 표준 Spring source
  layout과 요청한 Java package를 따라야 합니다. 그렇지 않으면 원본을 바꾸거나
  일부만 옮기지 않고 생성 전에 실패합니다.
- import는 과거 버전을 추측하지 않고 현재의 표준 Spring/frontend 구조만 검증합니다.
  선택한 template의 1.0 frontend source root가 맞지 않으면 원본이나 target을 일부
  변경하지 않고 생성 전에 실패합니다.
- `0.2.8` workspace, bundle, configuration, service unit을 그대로 승계하는 호환
  계층은 없으며, 필요한 코드는 새 `1.0` 프로젝트로 수동 이전합니다.

## 검증

- Maven 전체 테스트와 clean package
- 다섯 frontend template의 생성, dependency 설치, frontend/backend build
- Angular WIZ compiler 단위 테스트
- JAR/WAR bundle manifest 및 `SHA256SUMS` 검증
- custom API prefix, path versioning, OpenAPI, SPA fallback runtime smoke test
- Nginx/Apache2 image build와 non-root static file 접근 확인
- `wiz-spring --version`이 `1.0.0`을 출력하는지 확인
- `git diff --check`
