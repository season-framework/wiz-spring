# WIZ Spring 0.2.6

릴리즈 날짜: 2026-07-16

WIZ Spring `0.2.6`은 별도 `wiz-spring-instruction` 저장소에 있던 Codex 인스트럭션을 runtime JAR에 포함하고, `wiz-spring codex`와 Docker 개발환경이 외부 저장소 없이 같은 인스트럭션을 설치하도록 정리한 패치 릴리즈입니다.

## 주요 변경

- WIZ Spring Copilot 인스트럭션, short instructions, devdocs, prompts 74개 파일을 runtime JAR 리소스로 내장했습니다.
- `wiz-spring codex`가 `.codex/config.toml`, `.codex/AGENTS.md`와 함께 `.github/copilot-instructions.md`, `.github/devdocs/`, `.github/prompts/`를 생성합니다.
- `codex --check`가 MCP 설정뿐 아니라 내장 인스트럭션의 누락과 변경도 검사하며, `codex --force`로 관리 대상 파일을 최신 내장본으로 갱신할 수 있습니다.
- 인스트럭션 manifest의 경로를 검증하여 `.github` 밖으로 쓰거나 중복된 파일을 덮어쓰지 않도록 했습니다.
- Docker build에서 `wiz-spring-instruction` named build context와 `WIZ_SPRING_INSTRUCTION_DIR` 설정을 제거했습니다.
- runtime/bind image의 seed workspace는 `wiz-spring codex` 한 번으로 MCP 설정과 인스트럭션을 함께 포함합니다.

## 기존 workspace 갱신

기존 workspace를 다시 생성할 필요는 없습니다. runtime JAR을 `0.2.6`으로 교체하고 Codex 설정을 실행합니다.

```bash
runtime=/root/workspace/wiz-java/wiz-spring/target/wiz-spring-0.2.6.jar
workspace=/path/to/existing-workspace

java -jar "$runtime" codex --root "$workspace" --runtime-jar "$runtime"
```

기존 관리 대상 파일과 내장본이 다르면 명령은 파일을 보존하고 exit code `2`를 반환합니다. 차이를 검토한 뒤 내장본으로 갱신하려면 다음 명령을 사용합니다.

```bash
java -jar "$runtime" codex --root "$workspace" --runtime-jar "$runtime" --force
java -jar "$runtime" codex --root "$workspace" --runtime-jar "$runtime" --check
```

`.github/custom/`처럼 manifest에 없는 사용자 파일은 삭제하거나 덮어쓰지 않습니다.

## Docker 개발환경

별도 instruction 저장소나 named build context 없이 두 image를 빌드할 수 있습니다.

```bash
./build.sh all
```

생성되는 기본 태그는 다음과 같습니다.

- `registry.nanoha.kr/kwon3286/wiz-spring:0.2.6`
- `registry.nanoha.kr/kwon3286/wiz-spring:0.2.6-bind`
