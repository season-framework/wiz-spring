# WIZ Spring 0.2.6

릴리즈 날짜: 2026-07-17

WIZ Spring `0.2.6`은 Codex 인스트럭션과 설정을 runtime JAR에 내장하고, 모든 `wiz-spring create` 경로에서 workspace에 자동 설치하도록 통합한 패치 릴리즈입니다. Bash/Zsh completion도 command별 도움말과 option 설명을 함께 제공하도록 보강했습니다.

## 주요 변경

- WIZ Spring Copilot 인스트럭션, short instructions, devdocs, prompts 74개 파일을 runtime JAR 리소스로 내장했습니다.
- 기본 template, `--path`, `--uri` 중 어떤 방식으로 생성해도 `.codex/config.toml`, `.codex/AGENTS.md`와 내장 `.github` 파일을 자동으로 설정합니다.
- 별도 `wiz-spring codex` 하위 명령을 제거했습니다. Codex 설정은 workspace 생성 흐름의 기본 동작입니다.
- import source에 같은 관리 대상 파일이 있으면 현재 runtime의 내장본으로 갱신하고, `.github/custom/`처럼 manifest에 없는 파일은 보존합니다.
- instruction manifest의 경로를 검증하여 `.github` 밖으로 쓰거나 중복된 파일을 덮어쓰지 않도록 했습니다.
- `completion bash|zsh`를 추가하고 command별 usage, argument, option 설명을 표시합니다.
- Bash에서 같은 위치의 `Tab`을 반복해도 후보 목록으로 전환하지 않고 도움말을 유지합니다.
- completion 도움말에 command bold, option yellow, parameter italic 스타일을 적용하며 `WIZ_SPRING_COMPLETION_COLOR=false` 또는 `NO_COLOR=1`로 끌 수 있습니다.
- Docker build에서 별도 instruction 저장소 의존성을 제거했고, runtime/bind seed workspace는 `create` 한 번으로 MCP 설정과 인스트럭션을 포함합니다.

## Workspace 생성

packaged runtime JAR로 `create`를 실행하면 현재 JAR 경로가 `.codex/config.toml`의 MCP 설정에 자동으로 기록됩니다.

```bash
runtime=/root/workspace/wiz-java/wiz-spring/target/wiz-spring-0.2.6.jar

java -jar "$runtime" create /tmp/wiz-default --package com.example.default
java -jar "$runtime" create /tmp/wiz-path --package com.example.path \
  --path /path/to/source --skip-build
java -jar "$runtime" create /tmp/wiz-uri --package com.example.uri \
  --uri https://example.com/project.git --skip-build
```

MCP에 다른 runtime JAR 경로를 기록해야 할 때만 `create --runtime-jar <jar>`를 사용합니다. `WIZ_RUNTIME_JAR` 환경 변수도 같은 용도로 사용할 수 있습니다.

기존 workspace는 runtime 교체만으로 자동 변경되지 않습니다. 새 경로에 `create --path <existing-workspace>`로 가져올 때 자동 설정이 적용되므로, 전환 전 기존 config와 사용자 파일을 검토합니다.

## Shell completion

```bash
source <(java -jar "$runtime" completion bash)
source <(java -jar "$runtime" completion zsh)
```

도움말 패널은 `WIZ_SPRING_COMPLETION_HELP=false`, 색상은 `WIZ_SPRING_COMPLETION_COLOR=false` 또는 `NO_COLOR=1`로 비활성화할 수 있습니다.

## Docker 개발환경

별도 instruction 저장소나 named build context 없이 두 image를 빌드할 수 있습니다.

```bash
./build.sh all
```

생성되는 기본 태그는 다음과 같습니다.

- `registry.nanoha.kr/kwon3286/wiz-spring:0.2.6`
- `registry.nanoha.kr/kwon3286/wiz-spring:0.2.6-bind`
